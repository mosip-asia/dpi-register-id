# C2 — Liveness does not depend on MOSIP

## Previous

`/health` was a process check. `/ready` existed, and with the mock off it also called IDRepo. MOSIP can be down for minutes after a pause, and a readiness probe that calls it restarts the pod.

## Expected

`/health` is liveness only. `/ready` may check Redis and that configuration is loaded. It must not call IDRepo or Keycloak.

## Now

`/health` returns `status: ok` and does not touch Redis, IDRepo, or Keycloak. `/ready` pings Redis and checks that the MOSIP and Keycloak settings are non-empty. It does not call either service. With the in-process fallback on, those checks are skipped so local Compose still passes. Helm liveness is `GET /health` and readiness is `GET /ready`. Only liveness restarts the pod.

## What was done

The `/ready` handler was separated from the config predicate so the route returns the check body instead of a bare boolean. IDRepo `check_health` is not on that path. `ready_test.py` asserts a broken IDRepo client does not affect `/ready`.
