# C6 — Runtime dependencies the process actually imports

## Previous

The image installed numpy, pandas, scikit-learn, httpx, Django, and Celery. The container command is `uvicorn project.web:app`. Numpy, pandas, scikit-learn, and httpx were unused. Django was only the scaffold. Celery was a CLI demo imported while the server started.

## Expected

Drop unused Python dependencies from the runtime image. Keep libraries the server imports.

## Now

`[project].dependencies` is cryptography, fastapi, jinja2, psycopg2-binary, python-dotenv, redis, requests, segno, typer, and uvicorn. `uv export --no-dev` does not list Django or Celery. Celery and django-debug-toolbar are in the dev group. Importing `project.web` does not import Celery or Django. Redis stays because enrol limits, OIDC, audit, locks, staff, and tickets use it. `psycopg2-binary` stays because the local mock IDRepo storage imports it.

## What was done

The unused scientific and HTTP libraries were removed from the lockfile. Django left the runtime set. The Celery demo is imported inside the `processor_celery` commands, not at package import. `uv.lock` was regenerated.
