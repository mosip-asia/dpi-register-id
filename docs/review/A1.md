# A1 — Shipped image must not pretend the mock is IDRepo

## Previous

`IDREPO_INPROCESS_FALLBACK` existed and still defaulted toward the in-process mock. A failed or rejected IDRepo call could be written to `src/mock` and reported as a success with backend `mosip-idrepo-rest`. The runner image copied all of `src`, including the mock. `db/init-idrepo.sql` stayed on the local Compose overlay.

## Expected

The image that CI pushes does not fall back to the mock and does not report that path as a real IDRepo write. A rejected IDRepo response is HTTP 502. An unreachable IDRepo is HTTP 503. The mock and `db/init-idrepo.sql` remain available for local development only.

## Now

The fallback defaults off when the variable is unset. Helm sets `inprocessFallback` to `false`. With the flag off, a failed remote write does not call the mock and enrol returns 502 or 503. A mock write that local development still allows is labeled `inprocess-idrepo`. The runner stage deletes `/app/src/mock` after the source copy. Local Compose bind-mounts `./src/mock` read-only, including the mock IDRepo service in `docker-compose.mosip.yml`. `db/init-idrepo.sql` is not copied into the runner image.

## What was done

`inprocess_fallback_enabled()` treats unset or blank as off. `add_identity` only enters the mock branch when that flag is on, and it records `last_backend` as `inprocess-idrepo`. The Dockerfile runner stage runs `rm -rf /app/src/mock` before `USER 1000:1000`. Compose mounts the mock tree for local use. The import of `mock.idrepo` stays inside the fallback branch, and the CLI skips `mock.cli` when the package is absent so a production process still starts.
