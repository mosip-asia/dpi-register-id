# C5 — Digest-pinned image the Kit can pull

## Previous

Dockerfiles were not all pinned by digest. The workflow did not force `linux/amd64` or publish the image digest as a job output. The package lives on GHCR, which the Kit cannot pull anonymously. A visibility step tried to make the GHCR package public and was allowed to fail.

## Expected

Base images are pinned by digest. CI builds `linux/amd64` and publishes the image digest. The Kit deploy uses a mirrored digest on a registry it can pull. Making GHCR public is an organization-admin action and is not this repo's job.

## Now

The Dockerfile `FROM` lines use `@sha256`. CI sets `platforms: linux/amd64` and the job output `image-digest`. The visibility step only reads the package visibility. Helm `image.registry`, `image.repository`, and `image.digest` are the deploy contract. An empty digest still renders the GHCR tag for a local `helm template`. The chart README, NOTES, and deployment doc say a Kit deploy sets the mirrored digest and does not pull GHCR anonymously.

## What was done

The workflow records the build digest as an output and an artifact. The Helm helper renders `registry/repository@digest` when the digest is set. Copying `ghcr.io/mosip-asia/dpi-register-id@<digest>` to a registry the cluster trusts remains an operations step outside this repo.
