# A9 — One registration id for the whole attempt

## Previous

Every IDRepo write minted a new registration id. A lost response followed by a retry created a second registration.

## Expected

One registration id is kept for the whole enrolment attempt, including retries, and it survives a process restart. Redis is the store the rest of this app uses when `REDIS_URL` is set.

## Now

`_allocate` reuses `attempt.registration_id` and `attempt.uin` when the ticket already has them. With `REDIS_URL` set, the ticket (UIN, registration id, expiry, consumed flag, credential ticket) is stored in Redis for the ticket TTL. Clearing the process-local dict still returns the same registration id. A configured Redis that is down raises `EnrollTicketUnavailable` and does not fall back to memory. With `REDIS_URL` unset, the in-memory dict remains so tests and a single local process still work.

## What was done

`enroll_ticket.py` gained a Redis backend beside the in-memory dict. `remember_allocation` writes through that store. `generate_uin` is not retried, so a lost generator 200 is not followed by a second allocation on the same attempt. The credential ticket stays single-use.
