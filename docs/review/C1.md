# C1 — Helm chart, Kit vocabulary, no Istio, Kit-owned ingress

## Previous

Staging and production were described as Compose plus a Traefik overlay and an SSH deploy. The chart, where it existed, used `extraEnv` and `podSecurityContext` / `containerSecurityContext`, and it rendered its own Ingress. The Kit sends `extraEnvVars` and `securityContext`, owns ingress, and does not use Istio.

## Expected

A MOSIP-shaped chart (`replicaCount`, `image`, `resources`) renders with `helm template --kube-version 1.28.9`. No Istio. Compose is local-only. The Kit owns ingress. The chart accepts `extraEnvVars` and a pod `securityContext` as well as the existing keys.

## Now

`helm/register-id` has those values, uid 1000, read-only root, dropped capabilities, and no Istio objects. `extraEnv` and `extraEnvVars` are both applied. A pod `securityContext` merges onto `podSecurityContext`, and the Kit value wins on a duplicate key. `templates/ingress.yaml` is gone. The public host `register.<domain>` is the Service annotation `register-id.mosip.io/host`. CI renders the chart with Kubernetes 1.28.9 and checks that annotation. README, AGENTS.md, and the deployment doc say Compose is local and staging and production are this chart. `docker-compose.traefik.yml` remains an optional local overlay.

## What was done

The Ingress template was removed. The deployment template grew the alias keys. NOTES and the chart README stopped telling the installer to enable this chart's Ingress. The workflow assertion moved from an Ingress host to the Service annotation.
