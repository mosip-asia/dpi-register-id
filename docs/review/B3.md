# B3 — Write cap per enrolment ticket

## Previous

The cap was 30 successful writes per hour on one shared token, so every citizen shared one bucket. The first event expects about 100 enrolments.

## Expected

The cap is configurable and keyed per client or per ticket.

## Now

`ENROLL_SUCCESS_LIMIT` is read at runtime, defaults to 30, and is clamped to 1–10000. Helm sets `enrollSuccessLimit` to `100`. The bucket key is the SHA-256 of the enrolment ticket, not the email. A test with the limit set to 1 lets a second ticket succeed after the first ticket is exhausted. The window is one hour.

## What was done

`enroll_success_limit()` replaced the fixed 30. `POST /api/enroll` passes `attempt.ticket` into the limiter. The deployment template injects `ENROLL_SUCCESS_LIMIT`. The module docstring that still said "citizen email" was corrected to the ticket.
