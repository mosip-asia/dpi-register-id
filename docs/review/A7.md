# A7 — Public Keycloak URL and in-cluster Keycloak URL

## Previous

The browser redirect and the server-side token and admin calls shared one `KEYCLOAK_URL`.

## Expected

The browser uses the public host (`iam.<domain>`). Token exchange and the admin API use a different in-cluster host. One `KEYCLOAK_URL` must not satisfy both on a Kit deploy.

## Now

With `IDREPO_INPROCESS_FALLBACK` off, `/ready` requires both `KEYCLOAK_PUBLIC_URL` and `KEYCLOAK_INTERNAL_URL`. `KEYCLOAK_URL` alone does not pass. Authorization redirects use the public base. The code exchange and the admin client use the internal base. The production helpers do not substitute `KEYCLOAK_URL` when the fallback is off. Local fallback still may use one `KEYCLOAK_URL`, which is how Compose runs. Helm documents that `url` and `internalUrl` must both be set.

## What was done

`oidc.py` and `keycloak.py` gained scoped URL helpers that consult `inprocess_fallback_enabled()` before falling back. `router.py` checks the two variables on the Kit path. Helm values and the deployment env map both names. Compose passes them through, and the MOSIP overlay points the internal URL at the Keycloak service.
