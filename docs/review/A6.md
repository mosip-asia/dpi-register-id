# A6 — Keycloak admin by confidential client

## Previous

Provisioning preferred the master admin password grant and could fall back to a confidential client. Compose injected `KEYCLOAK_ADMIN_USER` and `KEYCLOAK_ADMIN_PASSWORD` into the app. The objectives note still said the token came from `admin-cli`.

## Expected

Only `client_credentials` on the application realm. Minimum realm-management roles `manage-users` and `view-users`. The secret is supplied per deployment, not generated by this chart and not a shared default password.

## Now

`get_admin_token` posts only `client_id`, `client_secret`, and `grant_type=client_credentials` to the application realm. The app does not read `KEYCLOAK_ADMIN_USER` or `KEYCLOAK_ADMIN_PASSWORD`. Compose does not inject them into the app. Helm reads `KEYCLOAK_ADMIN_CLIENT_SECRET` from `existingSecret` and says this chart does not create the client or the roles. The local Keycloak container still has its own bootstrap admin password so `start-dev` can run.

## What was done

The password grant and the `admin-cli` token call were removed. `.env.example` documents the confidential client and a local placeholder secret. The MOSIP Compose overlay no longer copies the master password into the app service. Realm roles remain a Kit assignment; this repo does not ship a realm export.
