# B2 — No shared enrol token

## Previous

A shared enrol token was baked into the JavaScript bundle. Anyone with the page could call enrol.

## Expected

Enrolment requires a server-issued, single-use, short-lived ticket. No token is rendered into HTML or the image.

## Now

`POST /api/enroll/ticket` returns `secrets.token_urlsafe(32)` and a TTL (`ENROLL_TICKET_TTL_SECONDS`, default 900 seconds, clamped to 60–3600). `POST /api/enroll` reads `X-Enroll-Ticket`. A missing, blank, or expired ticket is 401. After a successful enrol the ticket is consumed and a second use is 409. The SPA requests the ticket and sends it only as a header. `web/index.html` and the Jinja shell do not contain a token. The failed-enrol ticket can be reused until one write succeeds.

## What was done

The `VITE_REGISTER_ID_ENROLL_TOKEN` build argument is gone. `enroll_ticket.py` issues and checks tickets. The API dependency rejects a missing ticket before IDRepo or mail. Tests cover 401, 409, and that the ticket string is absent from the HTML response.
