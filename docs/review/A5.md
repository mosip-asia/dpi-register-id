# A5 — CBEFF only when the biometric policy allows it

## Previous

Enrol called `may_store_biometric_record(False, False)`, which cannot return true, so the CBEFF the code built was never sent. The README and the enrol write-ups said every enrol packages CBEFF and posts it, or they still described enrol as draft-only.

## Expected

The Kit face-enrolled contract expects an `individualBiometrics` document when policy allows it. The other choice was to stop building CBEFF and correct the README. This deployment sends the document when the face-api path passes.

## Now

A face-api enrol that passes the challenge, sweep, and frame checks calls `may_store_biometric_record(liveness.ok, True)`. When that is true, the body includes a CBEFF document with category `individualBiometrics` and `recordStatus` `biometric`. The hash-only path calls `may_store_biometric_record(False, False)`, stays `draft`, and does not build CBEFF. The README, user manual, business requirements, system diagram, and working-tree note say that.

## What was done

The enrol handler already had the policy function. The face-api path now passes a true engine flag after the checks succeed, and `_store_identity` forwards the XML only for a biometric record. The operational sentences were rewritten so they no longer say every enrol posts CBEFF and no longer say CBEFF is never sent.
